# PadLeak
对某款平板的破解尝试合集。仅作教学使用，请勿外传，下载后请自觉在24小时内删除。想了解更多详情请联系我邮箱（主页中）。（请勿在本项目中提及具体品牌或型号，哪怕只是猜测）。侵删。
有很多功能在过程中实现，但暂未发现实际推进作用，故不阐述。欢迎尝试。

##  0. 核心摘要
*   **设备型号**：讯飞 U10Pro（学校定制版，MTK MT6789 / Helio G99 芯片）
*   **系统版本**：Android 15
*   **初始状态**：系统被学校定制的 MDM（移动设备管理）全面接管。桌面锁定为“畅言智慧课堂”。无浏览器、无文件管理器、无通知栏、无微信/QQ/钉钉、无家长端。原生设置严重残缺（蓝牙不可用、关于本机仅 SN 可点）。电脑连接 MTP 无限卡死，USB 调试被锁死，C口音频禁用。（注：好像可以用手机直连，未尝试）
*   **目前结果**：通过纯软件与网络旁路手段，打通局域网文件传输（电脑至平板单向）、触发强制门户、分析 MDM 抓包流量，找到底层的 RSA 加密私钥。受限于 MDM 底层安装器（PackageInstaller）的强制拦截，未能成功安装第三方应用。

##  0.5 前置操作与初步尝试

**目标**：在无外部设备情况下恢复尽可能多的功能。
*   **回到原生桌面**：在学习桌面锁屏，锁屏界面时间右侧快速上下滑动屏幕，出现“暂无通知”通知栏后另一手指按住屏幕，停顿在该界面后点击“暂无通知”字样，下滑找到“阅读、回复和控制通知”，“Quickstep”，点击上方应用图标，下滑“主屏幕应用”，“Quickstep”。
*   **获取更多设置项**：桌面长按，“微件”，“设置”。
*   **启用更多应用**：进入“应用信息”设置，右上角“重置应用偏好设置”，多点几次直到计算器可用。注意该方法会导致默认打开方式失效，所有授权失效，回到正常学习应用需要重新授权。
*   **启用文件管理器**：进入“存储空间”设置，反复开关（最后打开）“存储空间管理器”。

##  1. 探索历程与技术细节复盘

### 阶段一：网络通道建立与强制门户突破
**目标**：打破文件的物理隔离，将外部文件传入平板。
> 笔者使用Dell Inspiron I320，Win8.1环境，执行`netsh wlan show drivers`提示有“网络承载能力”，其他配置可能需按需迁移。
*   **热点搭建**：使用 `netsh wlan set hostednetwork` 搭建热点。重启电脑需再次执行。[搭建说明](hotspot.md)
*   **Python DNS 劫持与 HTTP 服务器**：在电脑端使用 Python 编写脚本。监听 53 端口进行 DNS 劫持（将所有域名解析至电脑IP以触发强制门户登录，可自行了解），并在 80 端口架设简易 HTTP 服务器，返回一段定制的 HTML 代码。在该网页中植入 `<a>` 标签下载链接。成功将 APK 从电脑下载到平板。期间发现系统下载管理器会自动将大部分后缀强制改为 `.bin`，通过文件管理器手动重命名即可绕开。平板上传文件到电脑已实现相关代码，但该平板强制门户登录疑似未支持选择文件功能。[Python文件传输脚本](portal.py)
*   **可用文件格式**[此处](Formats.md)

### 阶段二：MDM 安装拦截与“包名伪装”对抗
**目标**：绕过应用安装白名单。
*   **测试 1（直接安装）**：通过文件管理器点击下载好的干净 APK（如 ES 文件浏览器），系统成功拉起 PackageInstaller 安装界面。但点击“安装”后，系统静默失败，抛出 **“未安装应用”** 错误。
*   **测试 2（包名伪装法）**：使用 `APK Editor Studio` 将目标 APK（如 WPS）的包名修改为平板内置应用（如 `com.zhixue.parent` 智学网），版本号改为 `999999999`，重新签名后传入平板。
*   **结论**：MDM 在 Android 底层的安装器（`PackageInstaller`）层面进行了深度劫持。即便系统解析了 APK 并弹出了安装确认框，MDM 仍会静默拦截（故意报“未安装”而非“被管控拦截”）。此外，系统内置的 `appUpdate` 文件夹也未触发本地升级逻辑。

### 阶段三：系统底层探索与 Intent 越狱尝试
**目标**：寻找隐藏的系统设置、开发者选项与 USB 调试开关。
*   **工厂模式（Factory Mode）**：通过“电源+音量加”进入系统底层工厂模式。发现了 `单项测试`、`调试测试项`、`版本信息`。但该工厂模式仅有硬件自检，无 USB Debug/ADB 开关。在此界面下没有自动启动adb。
*   **Intent 协议跳转**：在强制门户的 WebView 中，尝试使用 `intent://com.android.settings/#Intent;scheme=android-app;end` 尝试跳出沙盒。强制门户进程被杀死，网页瞬间崩溃闪退。

### 阶段四：中间人抓包与加密流量逆向
**目标**：分析 MDM 与云端的通讯机制，尝试伪造授权。
*   **抓包环境搭建**：使用 Reqable 配合修改版的 Python 脚本（将平板发往 80 端口的流量转发至 Reqable 的 9000 端口）。Win 系统底层的 `System (PID 4)` 或 `svchost.exe` 强行占用 80 端口，导致 `WinError 10013`。通过任务管理器强制结束进程释放端口，成功拦截流量。抓取到 `dcp.changyan.com` 等管控域名。发现其**未采用 HTTPS，而是纯 HTTP 明文传输**。但请求体（[点击此处查看](log.txt)）使用了严密的混合加密：
    *   `data` 字段：AES 加密的 Gzip 压缩数据。
    *   `encryptKey` 字段：使用 RSA 公钥加密的 AES 密钥。

### 阶段五：密码学解密与 OCR 物理死局（临门一脚，可能吧）
**目标**：利用设备内的 RSA 私钥解开通讯密文。
*   **线索发现**：在平板的文件管理器中（目录下与品牌同名文件夹有惊喜）意外获取了完整的 **RSA Private Key**。（此处想阅读需改后缀名为txt或html）[我截获的key](key.jpg)
*   **物理绝境**：由于无法通过电脑读取文件，只能依靠 **手机/平板拍照 + OCR 文字识别** 抄写私钥。在无衬线字体下，`I`、`l`、`1` 和 `O`、`0` 极度相似，导致数百个字符的私钥必然出现识别错误。
*   **对抗与修复**：
    1. 手动排查修改疑似字符（如修正了 `EG8` 行的混淆）。
    2. Python 编写正则脚本剥离非法字符，并强制对齐标准 Base64 长度（必须为 816 个字符）。
    3. 尝试多种 AES 的 IV（全 0、密文前 16 字节）。
*   **最终结果**：无论怎么修复，长度对齐后依然报错 `RSA key format is not supported` 或 `Invalid base64`。因为密码学校验要求 100% 精确，差一个比特，底层的数学公式（大素数乘积）就不成立。

## 2. 核心结论与技术总结（猜想）

1.  **关于 MDM 的流氓程度**：该设备的 MDM 并非简单的“桌面 App”，而是拥有极高权限的系统级组件。它接管了 `PackageInstaller`，屏蔽了 Intent 跳转。
2.  **关于加密协议**：虽然使用了 HTTP，但 AES+RSA 的双重加密确保了即便被中间人截获，没有完美私钥也无法伪造回传指令。**更重要的是，真正的锁在平板本地的安装器上，就算解开了云端 Token 也无济于事。**
3.  **关于 ADB**：如果设备无法在设置中开启 USB 调试，且工厂模式中没有 `adb` 开关，那么在 Android 15 下，电脑端强装驱动也无法绕过平板屏幕上的“授权弹窗”。物理隔离极其彻底。
